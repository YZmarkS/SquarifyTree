#+TITLE: Multithreaded Scan

Here are some initial thoughts on how to design a multithreaded directory explorer.

* Challenges and Concepts

In this section, we build up the understanding needed to design a multi-threaded directory scanner. We will review a reasonable single-threaded scanner, identify why it cannot be directly translated into a multi-threaded setting, then develop a multi-threaded algorithm using the lessons learned.

** Single-threaded DFS Scanner

Consider the following DFS implementation of directory scanning:
#+begin_src python
  class Inode:
      def __init__(path, usage=0):
          self.path = path
          self.usage = usage
          self.children = []

  def scan_dfs(path: Path) -> Inode:
      if (path is file):
          usage = usage_of_file(path)
          return Inode(path, usage)

      directory_inode = Inode(path)
      for entry in read_dir(path):
          child_inode = scan_dfs(entry.path)
          directory_inode.usage += child_inode.usage
          directory_inode.childen.append(child_inode)
      return directory_inode
#+end_src

There are a few benefit to this algorithm:
1. The output ~Inode~ has a shape isomorphism to the file structure.
2. Each subdirectory is scanned to completion before returned to the parent, making post processing unnecessary.

Naively, it would appear the ~for~ loop be parallelized. However, consider the following directory:
#+begin_src
  /
  ├── A
  │   └── AA
  └── B
      ├── BA
      │   ├── BAA
      │   ├── ...
      │   └── BAZ
      ├── ...
      └── BZ
#+end_src

This example demonstrates two challenges:
1. The task is too coarse grained, and we cannot know the task size until a directory is completely explored. This may lead to poor load balancing between threads.
2. Parallelizing at each directory level leads to unbounded thread count. It is likely we will pay more in overhead than actual computation.

** Single-threaded BFS Scanner

Consider the following single-threaded BFS scanner:
#+begin_src python
  def scan_bfs(path: Path) -> Inode:
      job_queue = deque([path])

      while job_queue:
          path = job_queue.pop_left()
          new_inode = Inode(path)

          if (path is directory):
              for entry in read_dir(path):
                  job_queue.push_right(entry.path)

          # Postprocessing

      return # root inode
#+end_src

This algorithm resolves the two challenges from before:
1. It is a reasonable assumption that the number of entries in a directory has a low variant.
2. This algorithm can run on any number of threads, which each thread running the ~while~ loop.

We need to address some additional challenges:
- From the algorithm, it is not clear when all the subtasks of a directory is complete.
- The disk usage of inodes need to be propagated back to ancestors.
